# Verifying the UI in the browser pane

Start the app with `preview_start {name: "dev"}` (`.claude/launch.json`).

For a wiki update preview or the automatic update notice, read `docs/agents/verifying-updates.md`. For offline support or the service worker, read `docs/agents/verifying-offline.md`.

Sections: the look and its references; driving the app; proving a style (colour and texture too); input and state; motion; performance; magnifying, sticky and scrolling; simulated conditions and seeded data; prototypes and stacked rows; reading and reloading; responsive layout; dialogs and keyboard; images and the server. Read the section your change touches.

## The look and its references

- **The settled look (pill bevels, fonts, colours) is recorded in `docs/prototypes/ui-verdict.md` and in CSS comments, beyond the PRD.** A ticket that changes the look edits those too, or they go stale.
- **Open the ticket's reference image with `Read` before building a visual change, and compare it with a zoomed screenshot before ticking a visual criterion.** A prose description of a reference can be wrong (a ticket said "dark fields" for a light-grey reference; the build was redone twice). Reference images live under `docs/reference/`; a ticket that names a reference without one there is missing it, so ask the owner for it first.
  - **A ticket whose decisions describe how something looks, with no reference at all, is missing one too.** Prose like "a small badge at its bottom-right" produced four redesigns of a 22px button (badge, ring, red/green dots, red dot). Before committing to a design, build the one or two candidates, magnify them (see below) and send the owner the screenshot with `SendUserFile`; build the one they pick.
## Driving the app

- **The app opens in the table (List) view; cards are the second button of `[aria-label="Display mode"]`.** Click it (`[...document.querySelectorAll('[aria-label="Display mode"] button')][1].click()`), wait about 600ms, then query `.entry-card` (a probe straight after load found 0 cards). To prove a status look on one card without changing stored progress, add `completed` or `notInterested` to its class, read `getComputedStyle`, and remove the class.
- **A bundled icon the content does not use is committed by hand into `public/icons/`.** `npm run snapshot` downloads only the icons the wiki content uses and never deletes, and the service worker precaches everything under `public/`, so a hand-added icon (#98's `Empty_content_icon.png`) works offline. Find a wiki file's path with `curl -sL https://ffxiv.consolegameswiki.com/wiki/File:<name> | grep -o 'mediawiki/images/[^"]*<name>'`.
- **Drive forms with `form_input`, `find` and `javascript_tool`.** Typing with `computer` into dialog fields lost keystrokes here, and a screenshot taken straight after an action can show the state before it.
## Proving a style

- **Measure a glyph's ink, not its box.** A text icon's line box can be centred while the drawn shape sits off (the footer chevron, #91). Draw icons as inline SVG, since fonts differ per browser and the pane is Chromium only; leave cross-browser alignment unticked under **Needs owner check**.
- **Prove styling with computed styles** (`getComputedStyle(el)` through `javascript_tool`: font family, size, transform), then take one screenshot for the owner.
- **A change to a colour, background or texture is measured, not judged by eye, and compared with `main`.** #129's first grain layer was flat grey at 10% alpha and lightened every panel; the owner saw it before any check did.
  - Read what a surface renders: `getComputedStyle` of `backgroundImage`, `backgroundBlendMode` and `color`, in the branch tab and in a `main` tab (the baseline recipe below), and diff them.
  - Measure a generated texture (an SVG data URI) by drawing it to a canvas: `const img = new Image(); img.src = url; await img.decode()`, `ctx.drawImage(img, 0, 0)`, then the mean and standard deviation of `getImageData`. A mean of 127.5 (mid grey) blended with `overlay` leaves the panel's own colour unchanged; the spread, times the panel colour's share of white, is the speckle's amplitude in brightness levels.
- **A subtle texture does not show in the pane's screenshots.** They are downscaled JPEGs, and the `zoom` action only crops. Prove the strength with the numbers above, look at it with CSS `zoom` (see "Magnify a small element" below), and leave "looks right against the game" under **Needs owner check**.
- **A change to shared styles (tokens, a rule many selectors read) is checked against `main`, state by state.** #119 found two regressions this way that a look at the page missed (a phone token shrinking the dialog titles; a `1em` heading merged into a smaller step).
  - Serve `main` beside the branch: `git worktree add --detach <scratchpad>/main-baseline origin/main`, then in PowerShell `New-Item -ItemType Junction -Path <worktree>\node_modules -Target <repo>\node_modules`, then `npx vite --port 5175 --strictPort` in the worktree (Bash, in the background: `launch.json` has no second server). Open it in a second tab with `tabs_create`.
  - Run one script in both tabs that walks the states (list, Cards, help dialog, Characters menu, Filters open with one box ticked, a toast from marking a row then Undo, the update preview) at 1500, 800 and 360px. It records, per text element, `fontSize`, `fontWeight`, `letterSpacing`, `lineHeight`, the first `fontFamily`, `textTransform` and `color`, keyed by the element's and its parent's classes plus its first 14 characters of text. Diff the two maps: only the intended changes may remain.
  - Clean up: `cmd /c rmdir <worktree>\node_modules` first (never `Remove-Item -Recurse` on the junction, it would empty the real `node_modules`), then `git worktree remove --force`, and stop the server on 5175.
- **Show the owner a screenshot with `SendUserFile` on the path printed under it** (`...\tool-results\mcp-Claude_Browser-blob-<n>.jpg`). For a before and after of a rule, inject the old rule with `!important` in a `<style id>` tag, screenshot, remove the tag, screenshot again: no second server needed.
## Input and state

- **Set up state through `localStorage`** (`contentUnlockLog.progress`, `contentUnlockLog.currentCharacter`), then reload: faster than clicking through the UI.
- **Wait about 500ms after an action, then read the page, before any screenshot or zoom.** A capture straight after a click, a reload or a style edit shows the old render; re-capture once before concluding a change did not apply.
- **Simulate pointer input the way a browser sends it.** A right click is `pointerdown` (`pointerType: "mouse"`, `button: 2`) then a cancelable `contextmenu`; a touch long-press is `pointerdown` (`pointerType: "touch"`), a wait past 500ms, then `pointerup` and `click`. A bare `contextmenu` reuses the last pointer type, so after a touch run it reads as a touch and does nothing. Re-query the row after each action and wait about 150ms before reading its class, since React replaces it. Entries keep their status in the pane's storage, so start each run by reading the status first, and press Undo or click back to Unmarked afterwards.
## Motion

- **A moving gradient band's "off the box" end is not 100%.** A `background-position` percentage is of the box minus the band, so a 50% band at `170%` still shows a slice. The owner found #97's sweep stuck at the right edge. Park a band of width *w* at `-w/(1-w)` and `(1+w)/(1-w)` (a 50% band: `-100%` and `300%`), and fade it out too. Read the end state with `getComputedStyle` after the duration and screenshot it before reporting a sweep done.
- **An effect drawn outside its box needs every ancestor's overflow checked.** The ring burst of #97 grew 17px out of a tile inside `.rail` (`overflow-y: auto` clips both axes) and was cut off; a ring on the pinned heading was also clipped by the scroller and painted under the tabs. Keep the effect inside its box, or compare its `getBoundingClientRect()` with each scrolling ancestor's at the animation's peak.
- **Freeze a frame the app would clear.** React state cleared by a timer unmounts the node and drops a paused animation. Before triggering, wrap `window.setTimeout` so that delay becomes `600000`, then `pause()` and set `currentTime` (the ring has a start delay: set past it).
- **Complete Shown asks for confirmation.** Its dialog buttons are `Cancel` and `Complete` under `[role=alertdialog]`. For a fresh state, call `localStorage.clear()` and reload in one call, and run the probe in the next: a reload inside a script cuts it off. Reloading also empties Undo.
- **Verify motion by its end state and by a frozen frame, not by class names.** A keyframe animation without `animation-fill-mode` snaps back to the base style when it ends (a sheen reappeared at the row's start). Wait past the duration and read the computed style again, then freeze a frame with `document.getAnimations().forEach(a => { a.pause(); a.currentTime = 150 })` and screenshot it. When a ticket describes the motion only in prose, send the owner that frame for each candidate before building the rest.
- **After changing table or row layout, click a row to mark it Completed and sample its size during the animation.** Read `getBoundingClientRect()` for the row and each `td` every 30ms for about 400ms: row height and cell widths must equal their values before the click. A row's `::after` became an anonymous cell and shrank a column only while the sheen played (#88); checking widths at rest missed it.
- **Probe motion in one script.** Click the trigger, then poll `document.getAnimations().some(a => a.animationName === "<name>")` every 10ms for about 600ms, and read the computed style (a marker's `transform`) mid-flight and after. Poll rather than reading once: the animation can start only after a long render. Skip a trigger that is already the chosen one, since clicking it plays nothing.
## Performance

- **A lag report, or any animation or resize near the entry list, gets the frame-gap probe below on the All tile (429 rows, the worst case), not on one expansion's 86 rows.** #94's filter bar slide was smooth on 86 rows and dropped to about 7 frames of 40ms on All. Each frame the slide resized `.scroll`, and the browser re-measured every row; `contain: size` on `.scroll` fixed it. Containment sizes the list from its flex parent, so recheck at 360×640, where the page grows with the list and the list collapsed to 12px until the rule was limited to `min-width: 761px`.
- **Measure performance in a production build, never the dev server.** React StrictMode renders twice in dev, so a stall seen there may not exist in production. Run `npm run build`, then `preview_start {name: "prod"}` (port 4173). Time a switch by recording `requestAnimationFrame` gaps around the click: `let last = performance.now(), go = true; const gaps = []; const f = (t) => { gaps.push(t - last); last = t; if (go) requestAnimationFrame(f); }; requestAnimationFrame(f)`, click, wait about 600ms, set `go = false`, and take `Math.max(...gaps)`. That gap is the freeze; about 16ms is a normal frame.
## Magnifying, sticky and scrolling

- **Magnify a small element with `document.documentElement.style.zoom = '5'`, then `scrollIntoView()` it and `zoom` the screenshot around its `getBoundingClientRect()`.** The `zoom` action only crops: a 22px control stays unreadable without the CSS zoom. Reset with `style.zoom = ''`.
  - **Scale page coordinates to screenshot coordinates before a `zoom` region or a click**: multiply by the screenshot's reported frame width ÷ `innerWidth`. The frame changes with the pane's size (800×911 and 396×575 were both seen), so read it from the latest screenshot.
- **CSS `zoom` cannot magnify something inside the entry list's scroller** (a pinned heading, a sticky header): at `zoom = '3'` the fixed-height window re-lays out and the screenshot shows the tile rail, not the list. Prove such a detail with `getComputedStyle` (`boxShadow`, `position`) and send the owner the plain screenshot (#96).
- **A backgrounded pane stalls `requestAnimationFrame` and scroll events.** A scroll-driven control (#99's jump buttons) never updated, and `scrollTo` through `javascript_tool` fired no `scroll` event, until a `computer` screenshot woke the pane. When a scroll-driven state will not change, take a screenshot, then rerun; do not rewrite working code.
- **A floating or sticky control gets compared with every control at both ends of the scroll.** The jump button covered the footer's Update button twice, and a sticky bar's rounded corners showed the list behind them mid-page; the owner found both. Scroll to `0` and to the very end, then test `getBoundingClientRect()` intersection of the control with each `button`, `a` and `input` on screen, and look at what lies behind its corners mid-page.
- **A phone rule in a `@media` block loses to an equal-specificity base rule later in `app.css`.** #99's Undo `height` and `margin-left` did not apply until the selector gained `button.` or `div.`. After a phone override, read the property with `getComputedStyle` before moving on.
- **Check a pinned or sticky element at scroll positions 0, 1, 5 and mid-list.** Read `getBoundingClientRect().top` minus the scroller's top at each; any difference is a jump the owner will see (#96's heading sat 4px low until the first pixel of scroll). Reset with `scrollTop = 0` and switch tile to check the list returns to the top.
## Simulated conditions and seeded data

- **Go offline for a UI check with `Object.defineProperty(navigator, 'onLine', { get: () => false, configurable: true })`, then `window.dispatchEvent(new Event('offline'))`, then wait about 600ms.** Reload to undo it. This covers UI that reads `navigator.onLine`; the service worker needs the recipe in `verifying-offline.md`.
- **Read a transitioning style twice, or after about 1 second.** A hover, pressed or on state with a CSS `transition` reads half-changed at 500ms (the background swapped, the label colour and shadow not yet). A page the pane has backgrounded animates slower still.
- **Rerun a check when the tool result says the user clicked in the page.** Their clicks interleave with your scripted ones and give a reading that contradicts the code; repeat it once before concluding anything.
- **Set a React input with the native setter, then dispatch `input` (text) or `change` (select).** Assigning `.value` directly is ignored: `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, "value").set.call(el, "text")` (`HTMLSelectElement` for a select), then `el.dispatchEvent(new Event("input", { bubbles: true }))`.
- **Feed a file to a file input without the native picker.** Build `new File([text], "b.json", { type: "application/json" })`, add it to a `DataTransfer`, assign `input.files = dt.files`, then `input.dispatchEvent(new Event("change", { bubbles: true }))`. The character menu's Import takes a backup this way.
- **Seed NEW entries without running an update.** Set `contentUnlockLog.newEntries` to a JSON array of entry IDs (`<unlock-slug>/<quest-slug>@<expansion-id>`, e.g. `["sastasha/its-probably-pirates@arr","copperbell-mines/into-a-copper-hell@arr"]`), reload, and remove the key afterwards.
- **Get a second character by editing `contentUnlockLog.progress`.** Add a record under `characters` (`id`, `name`, `world: ""`, `dataCenter: ""`, `level: null`, `updatedAt`, `deleted: false`) and reload. Afterwards delete the record, remove `contentUnlockLog.currentCharacter` and reload, so the pane's stored progress is left as found.
- **Set a character's level, then put it back, in two `javascript_exec` calls.** First `const p = JSON.parse(localStorage.getItem('contentUnlockLog.progress')); sessionStorage.setItem('orig', JSON.stringify(p)); p.characters[Object.keys(p.characters)[0]].level = 85; localStorage.setItem('contentUnlockLog.progress', JSON.stringify(p))`, then reload. At the end `localStorage.setItem('contentUnlockLog.progress', sessionStorage.getItem('orig'))`. Reset the level before a "no level" check.
- **Mark a row by clicking its `main tbody tr` (not a checkbox).** The only checkboxes on the page are the filter bar's, and they are disabled in Available now, so clicking one does nothing and the count you expected to move stays put. The Undo button in the hint bar puts the row back.
- **Reach an empty list by marking everything, then press Undo.** In Available now, Complete Shown then Complete empties it; Undo in the hint bar restores the entries, so the pane's stored progress is left as found.
## Prototypes and stacked rows

- **A current prototype lives on a `prototype/<name>` branch; once its design has shipped it is archived as an `archive/prototype-<name>` tag and the branch is deleted.** It is throwaway and based on an old `main`: read its component and CSS with `git show <branch-or-tag>:<path>`, and never diff it against local `main`. #124's `archive/prototype-stacked-row` diff against a stale `main` listed unrelated changes as the prototype's. A tool result that says "Output too large" holds only a preview: reread the saved file with `Read` before relying on the text.
- **A stacked row at 1000px and below has no `<table>`.** Probe `.stacked-row`, `.row-level` and `.row-chip`; `table.entries tbody tr` finds 0 rows at 390px and 429 at 1024px.
## Reading and reloading

- **Read a dialog with `find` and `read_page` on a ref, or a screenshot.** `get_page_text` returns only `<main>`: the whole entry grid (about 15k tokens), not the dialog.
- **Never reload inside a `javascript_tool` script.** `location.reload()` cuts the script off and loses its result; reload in its own call, then run the next script.
- **Make a scroll region scroll by shortening the viewport.** `resize_window` to 800×500, then compare `scrollHeight` with `clientHeight` on the region.
## Responsive layout

- **Check responsive layout with `resize_window`** (a narrow width such as 800 and a wide one such as 1500), and reset it with `preset: "desktop"` afterwards.
  - **The pane resets its own size** (when it is resized or the app redraws), so a reading can come from a different width than the one you set. Call `resize_window` in the same `browser_batch` as the probe, and have every probe return `innerWidth`; a number measured at the wrong width looks plausible (#132 read 1079px and 800px as 1500px).
  - **Find cells that wrap with this probe, run per column.** `td` index 2 is Unlock and 3 is Type; use `.line` elements, since a wrapped one is taller than its line height:
    `[...document.querySelectorAll('.entries tbody tr')].flatMap(tr => [...tr.children].flatMap((td, i) => [...td.querySelectorAll('.line')].filter(l => l.getBoundingClientRect().height > parseFloat(getComputedStyle(l).lineHeight) * 1.6).map(l => [i, l.textContent.trim()])))`
    Run it on the All tile (429 rows, every name in the bundled content) at 1500 and about 1100px, and read `th` widths beside it: `[...document.querySelectorAll('.entries th')].map(t => t.getBoundingClientRect().width)`. Wrapping at 1100px is expected for long names; at 1500px only the longest few should wrap.
  - **At 360×640, test sideways scroll in every view**, not only the default list: Filters open, Available now, Cards, the Characters menu. In `javascript_tool`, `document.documentElement.scrollWidth` must equal `clientWidth`, and `[...document.querySelectorAll('body *')].filter(e => e.getBoundingClientRect().right > innerWidth + 1)` must be empty. Also read each tab's `scrollWidth > clientWidth` on its text span: a tab can fit the page and still show "L. L. A.".
  - **A short laptop is 1280×560.** The window shrinks to fit and the list scrolls; check `.window` height against `innerHeight`.
## Dialogs and keyboard

- **Open the Characters menu with `document.querySelector('button[aria-label^="Current character"]')`** (`focus()` then `click()`). Its Reset button opens a confirm dialog on top, a second `.dialog` to check.
- **Measure a dialog's own width and height, not how it looks.** `.dialog` sets `width: min(380px, …)` and a later `.update-dialog` rule overrides it; a new dialog class with the same specificity placed earlier lost silently, and four screenshots of a 380px "wider" dialog looked plausible. Read `getBoundingClientRect()` of the dialog.
- **A dialog stays inside the app window: compare its rect with `.window`'s at 1600×1000, 1200×800, 800×500, 360×640 and 1280×560.** Under 516px of height the page scrolls and its scrollbar narrows the window, so 800×500 is the size that fails first.
- **Check a dialog's title bar or footer band fills it** by comparing the band's `getBoundingClientRect()` with `.dialog`'s: each side differs by the 3px frame.
- **Test keyboard behaviour with `computer` `key` (Tab, Escape), not a dispatched `KeyboardEvent`.** A dispatched event never moves focus, so it cannot show a focus trap. To open a dialog from a trigger and test focus return, call `trigger.focus()` then `trigger.click()` in `javascript_tool`; a bare `click()` leaves nothing focused to return to. The dev server runs React StrictMode, which mounts effects twice: a cleanup that moves focus runs once at mount and steals the dialog's `autoFocus`, so it must be deferred (`useModal` does).
  - **Read a `:focus-visible` style only after a real Tab.** A scripted `focus()` never matches `:focus-visible`, so the field reads as unfocused: press Tab with `computer` `key`, wait about 1 second, then read the computed style.
## Images and the server

- **Look at an image file (an icon, a generated PNG) with `Read`.** One call shows it. The pane opens a local file as a static snapshot: `screenshot` can hit the wrong tab and `navigate` rejects `about:blank`. Use the pane for pages the dev server renders.
- **Stop the server** with `preview_stop` when done. Test data stays in the pane's local storage.
- **Restart a stopped server with `preview_start {name: "dev"}`.** `navigate` to localhost fails and leaves a blank pane.
