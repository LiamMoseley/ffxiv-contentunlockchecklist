# Verifying the UI in the browser pane

Start the app with `preview_start {name: "dev"}` (`.claude/launch.json`).

- **Drive forms with `form_input`, `find` and `javascript_tool`.** Typing with `computer` into dialog fields lost keystrokes here, and a screenshot taken straight after an action can show the state before it.
- **Prove styling with computed styles** (`getComputedStyle(el)` through `javascript_tool`: font family, size, transform), then take one screenshot for the owner.
- **Set up state through `localStorage`** (`contentUnlockLog.progress`, `contentUnlockLog.currentCharacter`), then reload: faster than clicking through the UI.
- **Wait about 500ms after an action, then read the page, before any screenshot or zoom.** A capture straight after a click, a reload or a style edit shows the old render; re-capture once before concluding a change did not apply.
- **Set a React input with the native setter, then dispatch `input` (text) or `change` (select).** Assigning `.value` directly is ignored: `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, "value").set.call(el, "text")` (`HTMLSelectElement` for a select), then `el.dispatchEvent(new Event("input", { bubbles: true }))`.
- **Feed a file to a file input without the native picker.** Build `new File([text], "b.json", { type: "application/json" })`, add it to a `DataTransfer`, assign `input.files = dt.files`, then `input.dispatchEvent(new Event("change", { bubbles: true }))`. The character menu's Import takes a backup this way.
- **Seed NEW entries without running an update.** Set `contentUnlockLog.newEntries` to a JSON array of entry IDs (`<unlock-slug>/<quest-slug>`, e.g. `["sastasha/its-probably-pirates","copperbell-mines/into-a-copper-hell"]`), reload, and remove the key afterwards.
- **Get a second character by editing `contentUnlockLog.progress`.** Add a record under `characters` (`id`, `name`, `world: ""`, `dataCenter: ""`, `level: null`, `updatedAt`, `deleted: false`) and reload. Afterwards delete the record, remove `contentUnlockLog.currentCharacter` and reload, so the pane's stored progress is left as found.
- **Reach an empty list by marking everything, then press Undo.** In Available now, Complete Shown then Complete empties it; Undo in the hint bar restores the entries, so the pane's stored progress is left as found.
- **Show a wiki update without changing anything: patch `fetch` in the page.** Through `javascript_tool`, wrap `window.fetch` so a request to `consolegameswiki.com/mediawiki/api.php` runs the real fetch, edits `body.parse.text` (remove, rename or re-level a table row) and adds 1 to `body.parse.revid`, then returns `new Response(JSON.stringify(body))`. In the same script click the footer's update button and the dialog's Update; the preview then lists the edits. A reload removes the patch.
  - Match a fragment of a cell, not a whole sentence: links split the Information text (`Unlocks in the <a>Main Scenario Quest</a>.`). Change the unlock name to a new slug (punctuation alone keeps the ID, so it shows as Changed, not New and Removed).
  - Wrap `window.fetch` again to layer another edit. Click the dialog's Update by coordinate or ref (`find "Update"` misses it), then wait about 8 seconds for the live fetch.
  - Applying an update stores the new page. Afterwards remove `contentUnlockLog.content`, `.newEntries`, `.declinedMatches`, `.lastUpdateCheck`, `.dismissedRevision` and `.offeredUpdate` and delete the status keys you seeded, or the next run says "up to date".
- **Show the automatic update notice with an older device copy, not a patched `fetch`.** The check runs as the app opens, so a patch made after load is too late and a reload drops it. In one `javascript_tool` call: `const b = (await import('/src/content/bundled-content.json')).default`, deep-copy it, lower `revisionId` by 2, `shift()` an entry off `sections[0].entries`, remove `contentUnlockLog.lastUpdateCheck`, `.dismissedRevision` and `.offeredUpdate`, and store the copy as `contentUnlockLog.content`. Then `navigate` to the app: the bundle is newer, so the notice offers it with Review and Dismiss. Review lists the removed entry under New and leaves the stored revision unchanged; Dismiss writes `contentUnlockLog.dismissedRevision` and the notice stays hidden after a reload.
- **Read a dialog with `find` and `read_page` on a ref, or a screenshot.** `get_page_text` returns only `<main>`: the whole entry grid (about 15k tokens), not the dialog.
- **Never reload inside a `javascript_tool` script.** `location.reload()` cuts the script off and loses its result; reload in its own call, then run the next script.
- **Make a scroll region scroll by shortening the viewport.** `resize_window` to 800×500, then compare `scrollHeight` with `clientHeight` on the region.
- **Check responsive layout with `resize_window`** (a narrow width such as 800 and a wide one such as 1500), and reset it with `preset: "desktop"` afterwards.
- **Check offline support in Claude in Chrome, not the browser pane.** The pane cannot register a service worker (even a one-line one fails with "unknown error occurred when fetching the script"), and dev mode never registers one. `scripts/sw.test.mjs` covers the worker's logic against fakes; the real browser shows what fakes cannot (it found a `Vary: Origin` mismatch). Recipe, in order:
  - `npm run build`, then `npm run preview -- --port 4173 --strictPort` in the background. Not `npx vite preview --base /…`: Git Bash rewrites a leading `/` argument into a `C:/Program Files/Git/…` path.
  - `navigate` to `http://localhost:4173/`, wait about 4 seconds, then in `javascript_tool` read `navigator.serviceWorker.getRegistration()` (`active.state`), `navigator.serviceWorker.controller`, and `caches.keys()` with each cache's `keys().length` (shell cache about 62 files, `runtime-v1` the font files).
  - **Go offline by stopping the server:** `for pid in $(netstat -ano | grep ":4173 " | grep LISTEN | awk '{print $5}' | sort -u); do taskkill //F //PID $pid; done` (PowerShell's `Stop-Process` by port fails on PID 0). `navigate` again and check `#root` is not empty, `document.images` all have `naturalWidth > 0`, and `document.fonts` lists the four families as loaded. The wiki and Google stay reachable, so a resource's `workerStart > 0` and `transferSize === 0` show it came from the worker.
  - **A new deploy:** rebuild, restart the server, `navigate` once, wait about 5 seconds, then `caches.keys()` lists only the new `shell-<version>` and `runtime-v1`.
  - **A wiki icon the app does not ship:** wrap `window.fetch` (the "show a wiki update" recipe above) to replace `48px-Housing_icon.png` with `60px-Housing_icon.png` in `body.parse.text`, run Update from the footer, then check the three `<img>` elements with `consolegameswiki` in their `src` have `referrerPolicy` `no-referrer`, loaded, and that `runtime-v1` holds the URL. An icon-only change is adopted without a preview ("The log is up to date").
  - **Clean up:** `unregister()` each registration, `caches.delete` each cache, remove the `contentUnlockLog.*` keys, stop the server.
- **Stop the server** with `preview_stop` when done. Test data stays in the pane's local storage.
- **Restart a stopped server with `preview_start {name: "dev"}`.** `navigate` to localhost fails and leaves a blank pane.
