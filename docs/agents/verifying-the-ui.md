# Verifying the UI in the browser pane

Start the app with `preview_start {name: "dev"}` (`.claude/launch.json`).

For a wiki update preview or the automatic update notice, read `docs/agents/verifying-updates.md`. For offline support or the service worker, read `docs/agents/verifying-offline.md`.

- **Open the ticket's reference image with `Read` before building a visual change, and compare it with a zoomed screenshot before ticking a visual criterion.** A prose description of a reference can be wrong (a ticket said "dark fields" for a light-grey reference; the build was redone twice). Reference images live under `docs/reference/`; a ticket that names a reference without one there is missing it, so ask the owner for it first.
  - **A ticket whose decisions describe how something looks, with no reference at all, is missing one too.** Prose like "a small badge at its bottom-right" produced four redesigns of a 22px button (badge, ring, red/green dots, red dot). Before committing to a design, build the one or two candidates, magnify them (see below) and send the owner the screenshot with `SendUserFile`; build the one they pick.
- **Drive forms with `form_input`, `find` and `javascript_tool`.** Typing with `computer` into dialog fields lost keystrokes here, and a screenshot taken straight after an action can show the state before it.
- **Prove styling with computed styles** (`getComputedStyle(el)` through `javascript_tool`: font family, size, transform), then take one screenshot for the owner.
- **Set up state through `localStorage`** (`contentUnlockLog.progress`, `contentUnlockLog.currentCharacter`), then reload: faster than clicking through the UI.
- **Wait about 500ms after an action, then read the page, before any screenshot or zoom.** A capture straight after a click, a reload or a style edit shows the old render; re-capture once before concluding a change did not apply.
- **Verify motion by its end state and by a frozen frame, not by class names.** A keyframe animation without `animation-fill-mode` snaps back to the base style when it ends (a sheen reappeared at the row's start). Wait past the duration and read the computed style again, then freeze a frame with `document.getAnimations().forEach(a => { a.pause(); a.currentTime = 150 })` and screenshot it. When a ticket describes the motion only in prose, send the owner that frame for each candidate before building the rest.
- **After changing table or row layout, click a row to mark it Completed and sample its size during the animation.** Read `getBoundingClientRect()` for the row and each `td` every 30ms for about 400ms: row height and cell widths must equal their values before the click. A row's `::after` became an anonymous cell and shrank a column only while the sheen played (#88); checking widths at rest missed it.
- **Probe motion in one script.** Click the trigger, then poll `document.getAnimations().some(a => a.animationName === "<name>")` every 10ms for about 600ms, and read the computed style (a marker's `transform`) mid-flight and after. Poll rather than reading once: the animation can start only after a long render. Skip a trigger that is already the chosen one, since clicking it plays nothing.
- **Measure performance in a production build, never the dev server.** React StrictMode renders twice in dev, so a stall seen there may not exist in production. Run `npm run build`, then `preview_start {name: "prod"}` (port 4173). Time a switch by recording `requestAnimationFrame` gaps around the click: `let last = performance.now(), go = true; const gaps = []; const f = (t) => { gaps.push(t - last); last = t; if (go) requestAnimationFrame(f); }; requestAnimationFrame(f)`, click, wait about 600ms, set `go = false`, and take `Math.max(...gaps)`. That gap is the freeze; about 16ms is a normal frame.
- **Magnify a small element with `document.documentElement.style.zoom = '5'`, then `scrollIntoView()` it and `zoom` the screenshot around its `getBoundingClientRect()`.** The `zoom` action only crops: a 22px control stays unreadable without the CSS zoom. Reset with `style.zoom = ''`.
  - **Scale page coordinates to screenshot coordinates before a `zoom` region or a click**: multiply by the screenshot's reported frame width ÷ `innerWidth`. The frame changes with the pane's size (800×911 and 396×575 were both seen), so read it from the latest screenshot.
- **Go offline for a UI check with `Object.defineProperty(navigator, 'onLine', { get: () => false, configurable: true })`, then `window.dispatchEvent(new Event('offline'))`, then wait about 600ms.** Reload to undo it. This covers UI that reads `navigator.onLine`; the service worker needs the recipe in `verifying-offline.md`.
- **Read a transitioning style twice, or after about 1 second.** A hover, pressed or on state with a CSS `transition` reads half-changed at 500ms (the background swapped, the label colour and shadow not yet). A page the pane has backgrounded animates slower still.
- **Rerun a check when the tool result says the user clicked in the page.** Their clicks interleave with your scripted ones and give a reading that contradicts the code; repeat it once before concluding anything.
- **Set a React input with the native setter, then dispatch `input` (text) or `change` (select).** Assigning `.value` directly is ignored: `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, "value").set.call(el, "text")` (`HTMLSelectElement` for a select), then `el.dispatchEvent(new Event("input", { bubbles: true }))`.
- **Feed a file to a file input without the native picker.** Build `new File([text], "b.json", { type: "application/json" })`, add it to a `DataTransfer`, assign `input.files = dt.files`, then `input.dispatchEvent(new Event("change", { bubbles: true }))`. The character menu's Import takes a backup this way.
- **Seed NEW entries without running an update.** Set `contentUnlockLog.newEntries` to a JSON array of entry IDs (`<unlock-slug>/<quest-slug>@<expansion-id>`, e.g. `["sastasha/its-probably-pirates@arr","copperbell-mines/into-a-copper-hell@arr"]`), reload, and remove the key afterwards.
- **Get a second character by editing `contentUnlockLog.progress`.** Add a record under `characters` (`id`, `name`, `world: ""`, `dataCenter: ""`, `level: null`, `updatedAt`, `deleted: false`) and reload. Afterwards delete the record, remove `contentUnlockLog.currentCharacter` and reload, so the pane's stored progress is left as found.
- **Reach an empty list by marking everything, then press Undo.** In Available now, Complete Shown then Complete empties it; Undo in the hint bar restores the entries, so the pane's stored progress is left as found.
- **Read a dialog with `find` and `read_page` on a ref, or a screenshot.** `get_page_text` returns only `<main>`: the whole entry grid (about 15k tokens), not the dialog.
- **Never reload inside a `javascript_tool` script.** `location.reload()` cuts the script off and loses its result; reload in its own call, then run the next script.
- **Make a scroll region scroll by shortening the viewport.** `resize_window` to 800×500, then compare `scrollHeight` with `clientHeight` on the region.
- **Check responsive layout with `resize_window`** (a narrow width such as 800 and a wide one such as 1500), and reset it with `preset: "desktop"` afterwards.
  - **At 360×640, test sideways scroll in every view**, not only the default list: Filters open, Available now, Cards, the Characters menu. In `javascript_tool`, `document.documentElement.scrollWidth` must equal `clientWidth`, and `[...document.querySelectorAll('body *')].filter(e => e.getBoundingClientRect().right > innerWidth + 1)` must be empty. Also read each tab's `scrollWidth > clientWidth` on its text span: a tab can fit the page and still show "L. L. A.".
  - **A short laptop is 1280×560.** The window shrinks to fit and the list scrolls; check `.window` height against `innerHeight`.
- **Open the Characters menu with `document.querySelector('button[aria-label^="Current character"]')`** (`focus()` then `click()`). Its Reset button opens a confirm dialog on top, a second `.dialog` to check.
- **Check a dialog's title bar or footer band fills it** by comparing the band's `getBoundingClientRect()` with `.dialog`'s: each side differs by the 3px frame.
- **Test keyboard behaviour with `computer` `key` (Tab, Escape), not a dispatched `KeyboardEvent`.** A dispatched event never moves focus, so it cannot show a focus trap. To open a dialog from a trigger and test focus return, call `trigger.focus()` then `trigger.click()` in `javascript_tool`; a bare `click()` leaves nothing focused to return to. The dev server runs React StrictMode, which mounts effects twice: a cleanup that moves focus runs once at mount and steals the dialog's `autoFocus`, so it must be deferred (`useModal` does).
  - **Read a `:focus-visible` style only after a real Tab.** A scripted `focus()` never matches `:focus-visible`, so the field reads as unfocused: press Tab with `computer` `key`, wait about 1 second, then read the computed style.
- **Look at an image file (an icon, a generated PNG) with `Read`.** One call shows it. The pane opens a local file as a static snapshot: `screenshot` can hit the wrong tab and `navigate` rejects `about:blank`. Use the pane for pages the dev server renders.
- **Stop the server** with `preview_stop` when done. Test data stays in the pane's local storage.
- **Restart a stopped server with `preview_start {name: "dev"}`.** `navigate` to localhost fails and leaves a blank pane.
